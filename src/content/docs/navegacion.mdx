`id` es local al documento, explícito y no heredable. Su formato es `ref-nombre`; no debe repetirse entre tablas ni apartados de la misma página. Los números de fila y las claves internas de plegado no son identificadores estables.

## Sintaxis para autoría e IA

La jerarquía se declara en el frontmatter de cada documento:

```yaml
navigation:
  id: doc-000007
  parent: doc-000006
  order: 10
```

Un documento conserva su `id` si cambia el título o el archivo. Para trasladar una rama, cambia únicamente su `parent`. Reservar nuevos IDs con `npm run navigation:id`; nunca reutilizarlos ni inventar IDs ya emitidos.

Los enlaces Markdown usan la identidad documental:

```md
[Artículo 2](doc:doc-000007)
[Apartado del Artículo 2](doc:doc-000007#ref-desarrollo)
[Nodo de tabla](doc:doc-000010#ref-medida-detalle)
```

Para que un apartado conserve su destino aunque se cambie el título, usa un ID explícito:

```html
<h2 id="ref-desarrollo">Desarrollo</h2>
```

En componentes MDX puedes usar `DocLink`, que resuelve la misma referencia:

<ComponentExample source={linkSource} filename="navigation-link.mdx">

La ruta del import depende del archivo que lo utiliza. Para prosa, el enlace Markdown normal resulta suficiente. Un enlace HTML/MDX escrito como `<a href="doc:...">` no se transforma: usa Markdown o DocLink. Al compilar se generan enlaces HTML ordinarios y se comprueba que existen todos los documentos y destinos referenciados.

## Trasladar una rama sin mover archivos

En `articulo-2.md`, sustituye `parent: doc-000006` por `parent: doc-000009`. Los artículos 2 y 3 pasan bajo el Artículo 4. Conservan IDs y URLs; cambian automáticamente las migas, el árbol, el padre y el recorrido. Revierte ese mismo valor para recuperar la demostración inicial.

## Alcance actual

La jerarquía y las referencias se generan en el build. Las referencias a los IDs explícitos resisten cambios de título y se resuelven a la URL vigente al reconstruir. Las URLs antiguas no reciben redirecciones automáticas. Mantén el ID de destino al editar su texto.

Para recuperar el punto de lectura después de seguir una referencia, usa el enlace de retorno que aparece arriba del documento de destino. Cada documento ofrece una vista de su rama para lectura, impresión y descarga.

## Orden opcional, fechas y numeración

El navegador muestra una numeración consecutiva por nivel: `order` solo determina la posición. Por ejemplo, `10`, `20` y `30` se muestran como `1`, `2` y `3`; un hijo se muestra como `1.1`. Dos hermanos con el mismo orden comparten número. Los documentos sin `order` van al final y muestran **Pendiente de ordenar**.

Para desempatar se utiliza `created` del YAML y, si falta, `modified`, siempre con milisegundos y zona horaria:

```yaml
navigation:
  id: doc-000007
  parent: doc-000006
  order: 2
  created: "2026-11-17T16:05:12.037Z"
  modified: "2026-11-17T16:05:12.124Z"
```

Para dejar un documento pendiente de ordenar, omite la línea `order`; conserva su ID y padre. Entre los pendientes se compara también la fecha declarada. Las fechas físicas del archivo, Git o del build no intervienen. Si faltan ambas fechas o son idénticas, el ID estable resuelve el empate final. La raíz de la wiki no añade un prefijo 0, y un padre sin orden corta la numeración heredada.

El generador que produzca Markdown/MDX debe escribir esas fechas en el YAML de cada documento. Las marcas `.037Z` y `.038Z` se distinguen aunque pertenezcan al mismo segundo. Estas fechas no se actualizan automáticamente al compilar.


## Enlaces entrantes y salientes

Al pie de las páginas con referencias, **Enlaces salientes** reúne los destinos citados y **Enlaces entrantes** muestra qué páginas citan el documento actual. Cada entrada incluye el contexto de la cita. Si un documento cita el mismo apartado varias veces, cada referencia conserva su propio enlace al lugar donde aparece.

Prueba el recorrido desde el apartado **Desarrollo** del Artículo 2, usando el ejemplo «Salta al apartado del Artículo 2» de esta página. Al pie, busca «Medida de organización» en **Enlaces entrantes** y pulsa su enlace a Navegación. Volverás directamente a la cita de la tabla. Se selecciona **Resultado** y se abre la rama que contiene el enlace.

Para crear una referencia, usa un enlace Markdown `[texto](doc:doc-000007#ref-desarrollo)` o el componente `DocLink` en MDX. El enlace inverso se genera al compilar. Puedes usarlo para comprobar qué notas, tablas o explicaciones remiten a un apartado y recorrerlas sin duplicar enlaces al editar.

## Generar una copia local desde GitHub

1. Abre [Wiki · Build](https://github.com/PabloGonzalezRuiz/AstroXmind/actions/workflows/wiki-ci.yml) en GitHub.
2. Pulsa **Run workflow**, elige `main` para empaquetar la versión estable y confirma.
3. Abre la ejecución completada y descarga **AstroXmind-Wiki-Local** desde **Artifacts**.
4. Extrae el archivo descargado y luego `AstroXmind-Wiki-Local.zip`. Abre `Abrir-NAV-04.cmd` en Windows.

GitHub compila la wiki y prepara el paquete. Puedes pedir una copia nueva desde el navegador, sin instalar Node.js, npm o Python en tu equipo.


## Volver al punto de lectura

Sigue una referencia hacia otra página de la wiki y pulsa **Volver al punto de lectura** en el destino. La wiki recupera la posición, el foco en el enlace de origen, las pestañas de los ejemplos y el plegado de las tablas. Si encadenas varias referencias, puedes recorrerlas hacia atrás de una en una en la misma pestaña.

Puedes probarlo en la tabla plegable de esta página. Despliega la rama con «Medida de organización», sigue «consultar artículo 2» y usa el enlace de retorno en el Artículo 2. El enlace original debe recuperar el foco y la rama debe seguir abierta.


## Imprimir o descargar una rama

Pulsa **Imprimir o descargar esta rama** en la ruta de ubicación. La vista reúne el documento actual y todos sus descendientes en orden de lectura. Prueba desde Navegación para ver la serie y sus cuatro artículos, o desde Artículos de prueba para exportar solo esa subrama.

- **Imprimir o guardar como PDF** abre el diálogo de impresión del navegador. Elige la impresora o Guardar como PDF.
- **Descargar HTML** guarda un solo archivo. Ábrelo directamente en el navegador. El índice, los enlaces entre documentos de la rama y los saltos a citas funcionan sin conexión.
- Las tablas aparecen desplegadas y los ejemplos muestran su pestaña Resultado. Las imágenes locales compatibles se incluyen en el archivo. Los enlaces a otras ramas y a fuentes externas apuntan a sus direcciones en línea.


## Consultar una referencia en el panel lateral

Pulsa **Vista previa** junto a un enlace de referencia. El panel muestra un extracto del documento, apartado o nodo citado y mantiene abierta la página donde estabas leyendo. Puedes usar el ratón, tocar el botón o activarlo con el teclado.

En esta página, busca «Salta al apartado del Artículo 2» y pulsa el botón de vista previa que tiene al lado. Debes ver **Contenido**, el apartado del documento **Artículo 2 · Desarrollo**. Pulsa **Cerrar** o **Escape** para recuperar el foco en el botón. Si quieres seguir leyendo el destino, elige **Abrir documento completo**. Desde allí puedes usar **Volver al punto de lectura**.


## Mapa de conexiones

Abre **Mapa de conexiones** al pie de la página. El punto central representa el documento actual. Los números del dibujo corresponden a la lista de documentos enlazados. La lista indica si cada conexión procede de la jerarquía, de una referencia saliente o de una cita entrante. Varias citas entre los mismos documentos se agrupan en una sola conexión.

Desde Navegación, busca **Artículo 2 · Desarrollo** como referencia saliente y **Artículos de prueba** como hijo. Pulsa un título de la lista para abrir su documento. Si hay más de ocho conexiones, el dibujo muestra las primeras ocho y la lista sigue completa.
