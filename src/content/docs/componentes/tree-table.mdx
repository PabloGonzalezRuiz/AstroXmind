# TreeTable · tabla jerárquica

TreeTable representa una lista Markdown como tabla jerárquica. Las clases `nivel-0`, `nivel-1` y siguientes indican profundidad. La numeración se marca en cada nodo con una anotación entre corchetes. Los corchetes se escriben directamente en MDX, sin escapes.

## Numeración gradual · ruta desde el padre

<TreeTable numbering="path">

- TablaArbol
  - Nodo1 [numbering=arabic]
    - Nodo1Subnodo1 [numbering=arabic; tiered=true]
    - Nodo1Subnodo2
  - Nodo2 [numbering=arabic; start=7]
    - Nodo2Subnodo1 [numbering=arabic; tiered=true; start=5]
      - Nodo2Subnodo1Subnodo1 [numbering=arabic; tiered=true; start=3]

</TreeTable>

Se muestran `1.`, `1.1.`, `7.`, `7.5.` y `7.5.3.`. La raíz no lleva número porque no tiene marcador. `tiered=true` añade la ruta numerada de sus antecesores; si se omite, se muestra solo el número del nodo.

## Plegado heredable por rama

`collapsible="true"` habilita botones en los nodos con hijos. El valor se hereda; un nodo puede cambiarlo con `[collapsible=false]` o `[collapsible=true]`. Las ramas comienzan desplegadas. Un nodo deshabilitado permanece abierto, aunque un antecesor plegable puede ocultar toda su rama. Una hoja no muestra botón.

<TreeTable numbering="path" collapsible="true">

- TablaArbol
  - Nodo1 [numbering=arabic, collapsible=false]
    - Nodo1Subnodo1 [numbering=arabic; tiered=true]
    - Nodo1Subnodo2
    - Reactivar plegado [collapsible=true]
      - Descendiente con plegado heredado
        - Hoja
  - Nodo2 [numbering=arabic; start=7]
    - Nodo2Subnodo1 [numbering=arabic; tiered=true; start=5]
      - Nodo2Subnodo1Subnodo1 [numbering=arabic; tiered=true; start=3]

</TreeTable>

Las anotaciones aceptan comas o punto y coma y cualquier orden de opciones. La forma recomendada es `[numbering=arabic; collapsible=false]`. `collapsible` controla si se puede plegar; no indica el estado inicial. Sin JavaScript se conserva la tabla completa, sin botones inactivos. La numeración permanece estable al plegar. Cada tabla mantiene su estado por separado.

## Solo número entre hermanos

<TreeTable numbering="siblings">

- Grupo A
  - Elemento [numbering=arabic; start=4]
  - Siguiente elemento [numbering=arabic]
  - Reinicio en uno [numbering=arabic; start=1]
  - Continúa desde dos [numbering=arabic]
- Grupo B
  - Su propia secuencia [numbering=arabic]

</TreeTable>

Cada lista de hijos tiene su propio contador. `start=N` comienza o reinicia desde N; los siguientes nodos numerados continúan desde ese valor. Al entrar en otro padre, el contador empieza de nuevo salvo que se indique otro `start`.

## Sintaxis del lenguaje

La anotación entre corchetes es texto literal de Markdown/MDX; no hay que escapar ningún carácter. Se separan las opciones con punto y coma.

```md
- Nodo numerado [numbering=arabic]
  - Nodo con ruta acumulada [numbering=arabic; tiered=true]
  - Nodo que reinicia/continúa desde cinco [numbering=arabic; start=5]
```

- `numbering=arabic` activa la numeración decimal para ese nodo.
- `tiered=true` muestra la ruta de antecesores, por ejemplo `2.4.1.`; si se omite, muestra solo el número entre hermanos.
- `start=N` establece el número inicial. Los siguientes nodos numerados continúan desde él; volver a `start=1` reinicia la secuencia.
- El componente acepta `numbering="siblings"` o `numbering="path"`; con `numbering="none"` (valor por defecto) no muestra números.

## Correspondencia con XMind

En el JSON compartido, los nodos numerados llevan una extensión `org.xmind.ui.numbering` con `pattern: "numeral-arabic"`. Para la numeración gradual XMind añade `tiered: true` en la extensión del nodo correspondiente. AstroXmind representa esos datos como `[numbering=arabic]` y `[numbering=arabic; tiered=true]`. El JSON de referencia no muestra el comienzo de numeración; `start=N` es la ampliación del lenguaje para poder configurar el inicio y los reinicios.
